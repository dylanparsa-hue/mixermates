# Event readiness and verification — local Phase 7

Organizer/Admin → Event operations shows the selected event and readiness. This is a checklist, not an activation button. There are three separate outcomes: software configuration, human verification and authorization to sell. `salesAuthorized` remains false.

Automatic checks inspect configured event information and schedule, age restrictions, staff assignment, approved publication/configuration, explicit approved policy and current recipient state. Missing/UNCONFIRMED/TEST_ONLY fields stay visibly incomplete for a real event. Existing organizer and payment-recipient review records, notes/history and associated owned events are shown. Superseded, disabled, rejected and test-only recipients are distinguished; new bookings use only the eligible current version and old bookings keep their original snapshot.

A person must still verify organizer identity, responsible contact, event legitimacy, venue permission, supporting documentation where applicable, recipient ownership, current QR/account, approved refund/support responsibility and age/ID procedure. Review the actual evidence through the existing authorized admin workflow. Collect only necessary information through a separately approved procedure. No sensitive identity documents were collected in Phase7. Test approvals remain fictional and cannot establish genuine identity, bank ownership, law, licence or venue approval.

Before a real event: confirm date/time/timezone, capacity, entry options and fee/BYOB meaning; verify recipient identity and current QR; approve policy/refund rights, reservation/review deadlines and support contact; assign payment and registration reviewers independently; assign staff with the minimum entrance permissions; conduct physical-device and connectivity checks. All human checklist entries stay NEEDS_VERIFICATION in this local rehearsal.

Actual Halloween stays DRAFT / UNCONFIRMED / sales paused. The fictional rehearsal uses separate records. Neither software checks nor an administrator's test approval grants real-sales authorization. There is no sales override in this page.
