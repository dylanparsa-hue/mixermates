# Administrator guide

Phase 11 · localhost only. Sign in at `/admin/login` using the private fictional administrator access file. Never put its password in a report. Production access and live sales are not authorized.

- **Overview and Users:** inspect current counts, find accounts and review role/active state. Use the supported security controls for suspension or role/capability changes; these revoke sessions. Do not edit database rows to bypass permissions. An administrator cannot remove their own access through these controls. Do not grant real identities from fictional evidence.
- **Organizer/event reviews:** inspect organizer evidence and event submissions, current ticket/access configuration, moderation notes and the saved preview. Review outcomes are audited. Verification in this environment is test-only; it cannot certify a real organizer or authorize a venue.
- **Payment destinations:** compare the submitted recipient/version/private QR through the existing review screen. Approval requires an independent check and documented procedure; self-approval is denied. Reject or request correction when appropriate. Do not use historical recipient/QR references as current instructions. Disabling a destination stops new use and preserves original booking snapshots.
- **Event operations:** review proposed old/new terms, schedule and refund-policy changes independently. Use the current version; stale reviews must refresh. Approvals retain booking history and notify affected customers locally. Suspension and cancellation stop prohibited admissions. Do not create a sales-activation shortcut or override ticket eligibility.
- **Bookings and Refunds:** inspect separate registration, funds, BYOB, issuance and refund states. Receipt upload cannot confirm funds. Refund approval does not move money; transfer reporting and customer acknowledgement are separate. Reconciliation reports organizer receipts, not platform custody/revenue. Protect financial exports.
- **Support:** read private reports, record a safe response and change status using the supported controls. Responses persist for the authorized customer. Protect complaints and evidence; send no external message from this phase.
- **Audit log:** search/filter recorded actor, entity, state and time. Preserve history. Logs are application audit records, not tamper-proof external storage. Never delete financial or admission history to make counts look correct.
- **Operations:** inspect delivery failures/retries, unreleased expired holds, stale payment reviews, issuance recovery and recent operational/entrance activity. **Run local operational jobs** performs bounded expiry/reminder/mock-notification work; it approves no funds or registrations. **Request delivery retry** is bounded and audited. Resolve the cause before retrying. A local timeout is `LOCAL_TRANSPORT_TIMEOUT`; the worker retries with the same key. `MOCK_DELIVERED` means a test mailbox succeeded, not email delivery.
- **Missing ticket after funds confirmation:** preserve the original payment/reviews/recipient and resolve the fault, then choose **Retry eligible issuance**. Current eligibility is checked again. Do not ask for payment twice or create a duplicate credential manually.
- **Platform settings/readiness:** controls explain existing release locks. Software checks cannot supply genuine recipient/organizer/venue/device evidence or owner authorization. There is no permitted control to enable real sales in Phase 11.

If login, booking, database, privacy or entrance fails, follow [OPERATIONS_HANDOVER.md](OPERATIONS_HANDOVER.md). Recovery never resets the canonical database. Operational ownership, external providers and physical acceptance remain unverified. See [OWNER_ACTION_REQUIRED.md](OWNER_ACTION_REQUIRED.md).
