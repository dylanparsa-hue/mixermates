# Administrator operations — Phase 6

Use http://localhost:3011/admin/login. The isolated admin credential file is private at `/Users/parsa/.codex/tmp/mixermates-phase6-20261026/preview/.local/admin-access.json`. Do not publish it.

- **Overview** shows stored account/event/booking/review/support counts. “Active accounts” means accounts whose active flag is true, not monthly active people. Organizer-direct amounts are not MixerMates revenue.
- **Users** supports name/email/username search and 50 accounts per page. Review role, activity and organizer verification. Save a role or suspend/reactivate an account only after the explicit confirmation. Sessions are revoked. Own lockout is denied. Suspending an organizer account and moderating its events are separate actions; review its events as well. Never request a password/session/ticket token from a customer.
- **Event setup**, **Events** and **Verifications** reuse the existing review queue. Review event/access/age/schedule/tier/policy/payment configuration. Document changes/rejection/suspension reasons. Approve only a valid pending submission, and restore a suspended event only through the permitted administrator lifecycle. Cancelled/completed events cannot be restored. Sales remain independently disabled. Local fictional organizer/recipient approval does not verify real identity or banking ownership.
- **Booking reviews** reuses independent payment, registration, BYOB and issuer-recovery actions. **Bookings** shows the latest 100 records and links to review. **Payments** shows exact expected/confirmed direct-payment aggregates; no commission defaults are applied.
- **Refunds** provides platform oversight of the same organizer-direct requests. Review notes and recorded status history. A reported transfer requires a reference; the customer must confirm receipt. Admins cannot substitute their own unverified click for a customer's receipt. No money is transferred by MixerMates.
- **Support** and **Reports** open the same private case queue, latest 50 cases. Read the description and linked booking/event reference. Choose Under review, Resolved or Dismissed, then save a customer-facing response. Assignment records the reviewing admin. Closed cases cannot be silently overwritten; stale concurrent edits fail. This is a basic case workflow, without attachments, customer reply threads, reopening or external helpdesk integration.
- **Audit log** shows action, actor, role, time, target, old/new state and safe reason. Filter by action, actor, event or target; page through 50 rows. Raw passwords, credentials and receipt bytes are excluded. Private report audit notes are excluded from organizer event-log projections.
- **Notifications** is your own inbox, not every user's inbox. **Platform settings** explains the closed sales/release controls and unresolved email/commission configuration. It intentionally has no production activation button.

External mail, real-world verification, refund-policy eligibility, operational retention and release permission remain separate gates. No Phase 6 production operation is authorized.
