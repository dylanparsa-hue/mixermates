# Event operations guide — local Phase 7

Use http://localhost:3021/organizer with your fictional isolated account. Real sales remain disabled. Existing dashboard procedures are in ORGANIZER_OPERATIONS.md; the procedures below extend them.

## Before the event

Confirm software and human readiness separately in Event operations. Review recipient versions and keep booking snapshots intact. Agree the actual terms, contacts, reservation/review deadlines, responsibilities, capacity and age/ID procedure before any future sales authorization. Configure fictional tiers/forms/invitations only for this rehearsal. Review funds independently from screenshots; approve registration separately. Assign entrance staff with the minimum event permissions. Test camera/manual fallback and connectivity privately. Use a reviewed change request for date/venue/entry changes; never silently edit committed terms.

## During the event

Staff select the correct event and inspect current ticket status. Check the guest's required identification and age before acknowledging and confirming admission. Reject wrong-event, revoked, cancelled/suspended or already-used tickets. If connection fails, stop electronic admission and reconnect; the manual fallback still requires a live server decision. There is no synchronized offline admission. Escalate exceptions to the designated organizer rather than modifying payment/registration states at the door.

## After the event

Reconcile arrivals and private attendance without exposing Passport records publicly. Review refund/support workload, safe failure activity and undelivered essential notices. Use bounded retry/recovery only after checking eligibility; never approve funds or issue a ticket solely because a job was run. Retain audit/snapshot history. Resolve support privately and record customer receipt attestation separately from any bank verification. Apply an approved retention and operating procedure before real use; Phase7 did not invent one.
